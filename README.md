# 付款提审台

面向媒介项目费控的飞书多维表格自定义插件。用户在【付款执行明细】中勾选记录后，可以在插件内完成批次预检、附件归集、审批发起和状态回填。

## 核心流程

1. 读取当前表中 `申请付款选择框 = true` 的记录。
2. 根据员工选择的付款形式路由审批；不同付款形式不能混在一个批次中。
3. 提单前读取飞书审批定义，校验审批 Code、完整名称、控件 ID 和新增必填项。
4. 在插件内补充当前审批要求的临时附件，例如小荷包收款二维码；这些文件无需写回 Base。
5. 自动生成付款执行明细截图和 CSV，并与 Base 已有凭证一起上传到审批。
6. 通过 API 发起原生审批，随后把实例 Code、流程编号和状态回填到付款执行明细。

## 当前审批路由

当前运行环境没有 Test/Prod 模式切换，只是审批映射暂时指向带 `【测试】` 前缀的流程。正式上线时替换审批 Code、名称和控件映射即可。

| 付款形式 | 当前审批 | 金额 |
| --- | --- | --- |
| 对公支付 | `【测试】付款` | 实际成本合计 |
| 小荷包支付 | `【测试】小荷包` | 实际成本合计 |
| 云账户支付 | `【测试】云账户批量付款资源（仅达人）` | 实际成本合计 × 1.0665，四舍五入到分 |

没有配置的付款形式直接阻断，不回退到其他审批。`仅达人` 由员工选择付款形式时自行判断，插件不额外识别资源类型。

## 账户与附件规则

- `【测试】资源入库` 保留飞书原生收款账户控件。首次入库或账户变更时，由员工手工选择账户，让飞书完成银行、支行及省市校验。
- 付款提审时，从已通过的资源审批读取账户数据，并带入付款执行明细截图和 CSV；CSV 中 `开户省`、`开户市` 为独立列。
- 对公付款不通过 API 写入 `account` 控件，仅使用已解析的开户省、市做硬校验。任一字段缺失都禁止提审，并提示先完成资源账户变更审批。
- 小荷包二维码和审批补充附件由员工在插件内临时上传，提交成功后直接进入对应审批，不要求付款执行明细新增二维码字段。
- 实际打款仍由财务人工执行；插件只负责提审材料、审批发起和状态同步。

## 身份与权限

- 妙搭负责应用登录和运行时访问控制。
- 首次发起审批时，用户通过飞书 OAuth 授权；后续使用加密 HttpOnly Cookie 自动续期。
- 审批发起人是当前操作用户，不依赖个人电脑、CLI 或 Agent。
- App Secret、会话密钥、Base Token 和审批 Code 均通过妙搭环境变量注入。
